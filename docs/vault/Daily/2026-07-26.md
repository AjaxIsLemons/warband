## Opening Muster — icon-first decision system

Replaced the first run screen's universal `WarbandCard` adaptation with a dedicated desktop
Muster system.

- `MusterCardModel` allows exactly Health, Basic power + cadence, Reach, Signature, and Passive.
  It cannot accidentally inherit weapon footers, flavor paragraphs, prices, rank, or arbitrary
  stat rows.
- Added a code-native `WarbandGlyph` family for roles, scan stats, and kit keywords. Plain roles
  and keywords live in `UnitPresentation.json`; all mechanical numbers still come from the
  composed `UnitDef`.
- Added an in-portrait disclosure lens. Pointer hover is scoped to each fact/rule; keyboard focus
  opens a combined exact view. Weapon name, Mana per swing, crit, and cleave live only in the
  lens.
- `MechanicalRulePresenter` now owns base-attacks-to-signature math and full innate/passive
  language. Focused tests lock the opening cycles at Cleric 4, Bulwark 2, Shade 7, Sharpshot 5,
  Pyromancer 4, Berserker 3, Phalanx 4, Banneret 3.
- Replaced the numeric 0/3 chip with three ordered portrait sockets. Select/deselect transactions
  resolve before rebind; a full warband blocks replacement with “Remove one champion first.”
- Added tunable reveal, lens, select, deselect, blocked, ready, and socket-compaction timings to
  `HubPresentation.json`, reflected by F1. F2 exposes screen, fresh offer, lens states, transactions,
  blocked, ready, and validation previews.
- Added `IRunScreenLifecycle`: leaving Muster cancels every pending lens/reveal and clears the FX
  plane, preventing presentation from leaking over the following screen.

Mobile-specific composition remains deferred by explicit project direction. Verification target:
1920×1080 and 2560×1440, including initial, lens, 3/3, blocked, and reduced-motion captures.

**P1 (silently blocks friends playtest #1):** no run save/resume — CONTINUE is memory-only and the

### Built: ADR 0024 — per-act bosses + the disclosure contract
Picked the top *content* gap that is fully headless-verifiable (the Unity editor is a shared
singleton and Jake's focused editor is needed for captures). It turned out to be two problems that
had to ship together.

- **Act bosses.** Act 1 keeps The Last Oath (only boss with measured evidence). Act 2 **The Ashfall
  Battery** — Rooted gun behind two Colossi, shells your FARTHEST unit, leaves a burning crater, so
  the reflex "bunch behind the tank" loses. Act 3 **The Waning Crown** — bell fed by time AND by
  every death in its court, so clearing escorts is what rings it. Bosses take no act curve; the
  multiplier survives only past act 3 for endless, which keeps act 1 numerically identical and the
  oath probe's evidence valid.
- **The disclosure half was the bigger find.** `BuildFightBeat` hardcoded "THE LAST OATH" and
  disclosed nothing for the four node encounters, and `UnitCardFromDef` titles enemy cards from
  `ContentLexicon.Chassis(ChassisId)` — so an **Hourling previewed as "Shade" with the Shade's
  ability text**. ADR 0023 had already declared ChassisId a render key; the shell was treating it as
  identity. Brief and spawn now come from one method, the brief carries every body with a behavior
  sentence, and enemy cards use authored names and no portrait.
- **`--boss`, a new instrument.** Holds a boss to a harder bar than `--enc`: not win%, but *how many
  kinds of strength can pass it* (four parties — balanced/reach/control/damage). It caught the act-2
  boss posing nothing on its first run (three axes at 100% from **every** formation, spread 0); the
  bell went 14s → 9s against that measurement. Nice confirmation in the same table: act 2's control
  axis shows 50% rule-fired because Warden's Taunt Silences the gun and a Silenced clock never
  fires — the disclosed answer, observably working.
- **Gates:** 392 tests · scenarios round-trip and byte-stable across two runs · DLLs rebuilt · whole
  client compiled headless against Unity 6000.3.19 reference assemblies, with the gate itself
  negative-controlled (injected a type error, confirmed it was caught).
- **Not eyes-verified.** Two fixtures (`boss-ashfall-battery`, `boss-waning-crown`) were added via a
  new `encounter` seam in `scenarios.json` so either boss can be watched immediately. Contact sheet
  is now **10 fixtures, not 8**.
- **The bosses are not where runs die.** `--enc`'s naive line after the change: bot completes 3/12,
  and 7 of the 9 deaths are at **act 2 NODE fights** (4× at node 0 alone) — one at an act-2 boss,
  none at the act-3 boss. So act 2's node pool, not the new exams, is the wall. Relevant to board
  item 4 (pressure tiers) and item 14 (act identity); do not "fix" the bosses on this number.

## Roadmap grooming pass + item 7 (save/resume)

Jake asked for a grooming/priority pass, then "build it" on the outcome.

**Grooming.** Item 1 restaged **DESIGN→BUILD ⇒ VERIFY**: it contained a straight contradiction (the
beat sequencer called unbuilt in one paragraph, shipped in another) and all three of its failure
candidates have now been built against with none of it watched — so its blocker is Jake, not a
session. Gave it a four-thread index (1a spectacle VERIFY · 1b Hall polish · 1c Phase 4 **half**
built, `BattleForecast` has zero client references · 1d camera). Item 5's two "still scaffolding"
claims were false after ADR 0023/0024 and four of its seven remaining bullets were done → dissolved
to a laws page, residue pointed at items 2④/13/16. Item 10 gained the exact knob
(`impact.punchBoost`, global, default 0.8 — one F1 slider, not 197 tell rows).

**Jake's three decisions:** ① the content budget cap is **three acts, one boss per act** (it had said
"one act / do not expand", contradicting ADR 0019) — which promotes item 14 to real work; ② next
build order **7 → 8 → 9**; ③ **terminal loss stays**, save/resume is the mitigation, and act 2's node
pool is explicitly not to be tuned down for run length.

**Built item 7.** `RunSave` (in Warband.Run, no file IO — the run layer is pure, so the host owns the
bytes and the format stays headless-testable) + `RunController.Resume` (regenerates nothing, resolves
every content id eagerly so an old save fails with the id named) + client `RunSaveFile`
(temp-then-move, never throws, deletes what it cannot read) + autosave on `Rebuild()`, the shell's
single choke point. Hand-rolled `dotted.key=value` format because Warband.Run has zero package
references by law and IL2CPP strips reflection. **412 tests.** The one that matters: a run saved,
serialized and rebuilt from text plays out *identical* to one never saved — same battles
event-for-event.

**Verified on Windows, and one permanent constraint found.** New committed harness
`Assets/Editor/RunSaveCheck.cs` (menu `Warband/Verify Run Save`, edit-mode, MCP-drivable) proved the
real platform path: save at `AppData/LocalLow/InhouseBoyz/Warband`, bytes survive Windows text IO,
no CR in the record separator, resume matches on every axis. 12/12 PASS, console clean.
Then: **`EditorApplication.EnterPlaymode()` is refused over MCP** — *"User interactions are not
supported for MCP tool calls."* **Play Mode is unreachable from any session, permanently.** So button
wiring and anything frame-driven is Jake-only verification. The workable substitute is exactly what
`RunSaveCheck`/`RenderShots` do: a committed edit-mode Editor script driven by `ExecuteMenuItem`
against the real DLLs. Added to the client gotchas. Item 7's shell wiring is therefore built,
compile-checked and platform-verified at the save layer, but **not clicked through**.
