# 2026-07-24 — data-driven replay pipeline + signature-matched tells (client renders REAL builds)

Overnight autonomous session (Jake handed the wheel: "build SYSTEMS we configure with data to
add/alter stuff, probably replay/rendering"). Board item 4b advanced; two new systems landed,
both eyes-verified through the client. **165 → 169 tests.**

- **DATA-DRIVEN REPLAY PIPELINE.** The client had been rendering ONE hardcoded toy skirmish
  (`Viewer.SampleArmies` — hand-built capsules). Now fights are authored as *data*:
  `sim/Warband.Viewer/scenarios.json` describes each unit as a real `Catalog` build (chassis +
  B/A/S path picks + weapon/tier/mastery/rank + optional banners). `make scenarios` composes them
  via the same `Loadout.Compose` path the sweep proved → 5 diverse replays into the client's
  `StreamingAssets/replays/` (duel · castfest · stomp · statusstorm · skirmish), each round-trip
  checked (client view-hash == live fight). Viewer now references Content+Run. This is the
  "contact-sheet" backbone: one data file → many diverse fights for the render layer to tune against.

- **`ReplayInspector` (Warband.Sim, tested).** Folds a replay into its distinct PRESENTATION
  signatures — Damage by `Cause` + crit, Status by kind, Field wall/zone — with counts, amount
  ranges, tick spans. This is the "what tells does this fight actually need?" tool. `make coverage
  F=<replay>` prints it; `make scenarios` prints one table per fixture. The coverage across the 5
  fixtures is rich: crits, Taunt, Phase, Burn, Counter, CheatDeath, Leap, fields, storm, the full
  status vocabulary — exactly the authoring checklist for the tell layer.

- **CLIENT RENDERS REAL CATALOG BUILDS — eyes-verified.** Pointed `ReplayPlayer` at each scenario
  (zero code — it already loads by path) and captured via the MCP render-to-PNG + scp loop. All 5
  render correctly: real hero kits marching + engaging on the hex board, team-zone tints, aura/burn
  fields as tiles, HP/shield bars, floating damage/heal numbers, full URP diorama post-stack (bloom,
  vignette, tilt-shift DoF). This is the "not toy capsules anymore" milestone.

- **SIGNATURE-MATCHED TELLS.** Tells keyed only on `EventKind` before, so Burn damage couldn't read
  differently from a sword hit and statuses had no dedicated tell. New `TellMatch` (Warband.Sim,
  tested — a rule matches on kind + optional Cause/StatusKind, and the MOST specific rule wins;
  filterless = fallback). `TellDef` gained `byCause`/`byStatus` filters; the FeedbackDirector was
  rewritten to dispatch through TellMatch. Authored the fuller closed vocabulary purely in
  `tuning.json` (no code per tell): Damage/**Burn**→orange · Status/**Taunt**→purple ·
  Status/**Stun**→violet · Status/**Phase**→cyan, alongside the existing white-hit / gold-crit /
  cyan-cast / green-heal. Verified in captures: an orange burn-flash beside a white attack-flash;
  twin purple Taunt flashes + a cyan Phase shimmer. Jake/agent add or retune any signature's tell
  by editing JSON — the matcher precedence is the only logic, and it's headless-tested.
